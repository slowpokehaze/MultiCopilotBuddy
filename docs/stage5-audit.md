# Этап 5: аудит мульти-сессий CopilotBuddy и выбранная архитектура

Дата: 2026-11-19. Источники: `thirdparty/copilotbuddy-master.zip` (Styx),
`thirdparty/wow-autologin` (wow-manager), живой бот `CopilotBuddy.exe` 1.6.7.6.

## 1. Что глобально в CopilotBuddy

- `StyxWoW` / `ObjectManager` / `BotManager` — статические классы: весь стейт
  бота живёт в **процессе** бота. Два процесса бота = два изолированных
  стейта, рефакторинг «per-session контекста внутри одного процесса» не нужен.
- `Styx.ProcessMutex` — именованный мьютекс **per-WoW-PID**
  (`MachineName ^ pid ^ tz ^ "CopilotBuddy"`): защищает от двойного аттача к
  одному клиенту, но **не запрещает** параллельные боты на разных клиентах.
- `Logging` — файлы логов именуются по PID бота (`Logs/`), записи не
  пересекаются. `Logging.ApplicationPath` = папка бота.
- `CharacterSettings` — `Settings/CharacterSettings_{Name}.xml`: имя персонажа
  без реалма. Коллизия возможна только при одинаковых именах персонажей на
  разных аккаунтах/реалмах.
- Компиляция плагинов (`PluginManager.RefreshPlugins`) пишет во временную
  папку; одновременный старт двух ботов в одной папке теоретически может
  состязаться за кэш компиляции. На практике старты разнесены cooldown'ом
  лаунчера (20 с+) и лимитом аттача (30 с).

## 2. Вывод

Полный рефакторинг не окупается: параллельные сессии достигаются **N
процессами** `CopilotBuddy.exe`, каждый со своим `/pid=<WowPid>` (так уже
работает `BotAttacher` + `SessionManager`).

Остаточный риск — общие файлы папки бота. Решение двухуровневое:

1. **По умолчанию** — одна папка на все сессии (риски выше перечислены и
   приемлемы).
2. **Опция `Launch.BotCopyPerSession`** (`MultiAccount.json`) — по копии папки
   бота на сессию (`<bot>\MCBBots\<id12>\`, без `Logs/Cache/WTF/Crashes`).
   Включать при одинаковых именах персонажей или отладке плагинов.

`MCBBridge`-плагин уже не зависит от этого выбора: порт сессии и PID WoW
передаются через `Plugins/MCBBridge/sessions.json`, который пишется в папку
конкретного бота (оригинал или копию) при каждом аттаче.

## 3. Ограничения fallback-режима

- Каждый процесс бота — полный экземпляр (~50–100 МБ RAM) + свой UI.
- Обновление бота = обновить оригинал и удалить `MCBBots\` (копии
  пересоздадутся при следующем аттаче).
- Внутриигровые аддоны (MCBuddy) — общие для всех клиентов (клиентские
  папки), коллизий нет: SavedVariables per-account.
